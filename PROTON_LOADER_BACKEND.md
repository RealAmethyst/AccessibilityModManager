# Steam Proton loader backend

The Linux manager installs a verified Proton package into a detected Steam game, configures that game's prefix when needed, and owns one reversible Steam launch option. The game still starts from Steam Play. Amethyst confirmed the updated wrapper keeps Time Stranger working as on Windows. New games still need a live check before their releases are called compatible.

## Authoring a new game

Both the Windows and Linux AuthorTools can build a `proton` package with the shared package builder. Put the complete, pinned Windows loader, mod, Prism Windows DLL, matching Prism Wine bridge and license notices in the source folder. The tool copies the folder structure, adds file verification for launch assets, and writes the Steam setup metadata. Enter the Steam app ID and executable exactly as they appear in the game's Steam installation. The release record takes its platform from the validated ZIP. Use a separate version number for a Proton release, as Amethyst requested.

Choose a launch mode based on the loader's real startup path:

- `direct`: Steam launches the original game executable. Use this for a DLL proxy loader. Declare each required Wine DLL override, for example `version=n,b` for a verified MelonLoader `version.dll` or `winhttp.dll=n,b` for a verified BepInEx `winhttp.dll`. The proxy DLL must be present in the package and installed at its declared game-relative path. Most proxies sit beside the game executable; `wineDllProxyPaths` can name a subfolder such as `app_digister/freetype.dll`. A Reloaded II ASI proxy can also use this mode if its actual game import and loader startup have been verified.
- `replaceExecutable`: Steam's game executable argument is replaced by a bundled Windows launcher. The launcher receives the original executable's Windows path (`Z:\...`) as its first argument, as a Windows Image File Execution Options redirect would pass it. Time Stranger uses this because its tested startup path needs its own suspended-child injection sequence. The launcher is a declared package file, not a manager branch for that game.

For a Reloaded II release, provide `reloadedRoot` and `reloadedModId` together. The manager writes the loader pointer inside that game's Proton prefix and an app configuration under the declared loader root. It refuses an existing different pointer. The wrapper marks that configuration ready on launch. Either launch mode can carry this prefix setup.

For Prism under Proton, include the matching Windows Prism DLL and placeholder DLLs beside the mod, plus the Linux `.dll.so` host modules in the declared `bridgeDirectory`. The wrapper prepends that directory to `WINEDLLPATH` and keeps any existing path. A release without Prism leaves `bridgeDirectory` empty.

For a Windows Desktop Runtime prerequisite, declare its `major.minor.patch` version and the official x64 installer SHA-512. The manager downloads from Microsoft's versioned `builds.dotnet.microsoft.com` path, verifies the exact SHA-512, runs it as the normal Unix user inside this game's Proton prefix, and verifies both .NET and Windows Desktop frameworks there. Legacy Time Stranger packages can omit the hash for their already pinned 9.0.20 runtime. Windows elevation prompts and Windows lifecycle installers are not run by the Linux manager. Put loader files in the package and describe supported prefix prerequisites instead.

For native Windows DLLs and EXEs in a verified Proton package, the manager checks their PE imports for `msvcp140*.dll` and `vcruntime140*.dll`. If needed, it checks the matching x64 or x86 Visual C++ v14 runtime in that game's prefix, installs Microsoft's pinned 14.51.36247.0 redistributable quietly, and verifies the installed version before copying mod files. This applies to explicit Proton packages and converted Windows releases on install or update. The pinned installer is verified by SHA-512. The redistributable remains in the shared game prefix after mod uninstall; removing it could break the game or another mod. An already installed mod is not retroactively checked until update or reinstall. Import inspection cannot discover a runtime loaded only with `LoadLibrary`, so package authors should declare and validate unusual prerequisites in an explicit Proton package.

The package manifest's existing dependency list also works in the Linux manager. A `framework` dependency can use a game-relative file check written with Windows or Unix separators, and a missing dependency can use the existing hash-checked `extractZip` or `copyFile` auto-install path. The manager asks for consent before downloading and supports the existing manual-dependency pause. Registry and absolute system checks cannot verify a Proton installation, and `runInstaller` Windows executables are refused before download. Public catalog game definitions use the same platform gate.

Dependencies can now declare `targetPlatforms` with any combination of `windows`, `proton`, and `linux`. The AuthorTool dependency editor exposes these choices. An omitted list keeps legacy behavior: try the dependency on Windows and Proton, subject to Proton's supported checks and install actions. The package builder includes only dependencies applicable to its package target. An explicit Windows-only dependency is skipped for Proton.

## Automatic setup for Windows releases

Authors publish only the Windows release. The Linux manager converts the verified Windows package into a temporary Proton package by reading what the mod installs, not by matching known loader names. `ProtonLaunchAnalyzer` applies Windows' own loading rules to the planned files of the package and of its pinned `extractZip` framework dependencies:

- **DLL beside the game that Proton also supplies.** Windows loads a DLL from the game's folder before its system copy; Wine prefers its built-in module. Each such DLL gets a native-first override (`name=n,b`). The built-in list is read from the selected Proton's `files/lib/wine/x86_64-windows` or `i386-windows` folder. This covers BepInEx `winhttp.dll`, MelonLoader `version.dll`, ASI loaders such as `dinput8.dll`, and similar proxies without per-loader code.
- **DLL the game imports or already ships.** It loads under Wine without an override, for example DSCSModLoader's `freetype.dll`, which Proton does not supply.
- **Bundled launcher.** An EXE that imports `CreateProcess`, `WriteProcessMemory` and a remote-execution call (`CreateRemoteThread`, `QueueUserAPC` or `SetThreadContext`) starts the game and injects into it. It replaces the game executable in `replaceExecutable` mode. More than one such launcher is refused as ambiguous.
- **Loader installed before the mod.** A recognized BepInEx, MelonLoader or DSCSModLoader proxy already beside the game is reused and stays outside the mod's file ownership.
- **No way to load.** A package that installs code without any of the above is refused, so a game never starts silently without its accessibility mod.

When the catalog does not name the game executable, the Linux manager reads Steam's binary app cache (`appcache/appinfo.vdf`, formats 27 to 29) and uses the single Windows default launch entry Steam itself starts, for example `exe/MMBN_LC2.exe` for Battle Network Legacy Collection Vol. 2. Without one unambiguous entry it falls back to the earlier title-matching search. Loader files must sit beside that executable: a release that installs a loader such as `dxgi.dll` elsewhere cannot load on Windows either, and the manager refuses it with a message naming the loader and the executable.

Every loader DLL must have the game's PE architecture. The manager checks each native-first DLL again after install. A `*.runtimeconfig.json` in the package declares a shared .NET requirement; the newest requirement is used because mod components load into their host's runtime. The manager installs the newest official x64 Windows Desktop Runtime of that major.minor channel, with the SHA-512 taken from Microsoft's release metadata at `builds.dotnet.microsoft.com`. The already pinned 9.0.20 runtime is used offline for 9.0 requirements up to that version.

It checks the package and dependency hashes, manifest and file destinations before planning the launch. Dependencies are installed with the normal consent, verification, receipt and uninstall flow. Supported Prism 0.18.3 x64 builds gain matching Wine host modules and PE placeholders. The published Cyber Sleuth plugin is the verified exception: its Prism 0.17.3 Windows DLL registers no Orca or Speech Dispatcher backend. The adapter keeps that plugin's older Prism configuration ABI through a small verified DLL, stages pinned Prism 0.18.3 as `prism-core.dll`, and places the 0.18.3 placeholders beside both DLLs in `resources/plugins`. Other Prism 0.17.3 consumers fail closed because their API use has not been audited. When a package carries the verified legacy Tolk x64 DLL, the temporary Proton package replaces that DLL with Prism's official Tolk compatibility shim and adds the matching Prism DLL and bridge. The published Windows ZIP and mod DLL remain unchanged.

Wine DLL override names may include `.dll` or omit it. `WineDllProxy` resolves both spellings to one module name and the same default `module.dll` path for package checks, authoring, conversion and installed-proxy verification. The Steam override retains the package's original spelling and native-first order.

The ABI DLL's source is `src/AccessibilityModManager.Infrastructure/Assets/Prism0173Compat/prism_compat.c`. It implements the 15 Prism exports used by the published Cyber Sleuth plugin, translates the 48-byte version 3 configuration into Prism 0.18.3's 56-byte version 4 configuration, and loads `prism-core.dll` from its own directory. The embedded PE has SHA-256 `f2f234b8ec3b0f6c0df5f4e501232e8e9c20a1299c885ffc7e19ef90559ab6ec`; `installer/linux/check-prism-0173-compat.sh` rebuilds it with the pinned LLVM MinGW toolchain and checks byte identity. An offline Proton probe using the published version 3 header selected Orca and received Prism's already-initialized result, which the plugin treats as success. This probe did not emit speech or launch the game.

A bundled Reloaded II release is converted by the same rules: its launcher is detected from its imports, and its `Reloaded.Mod.Loader.runtimeconfig.json` sets the .NET requirement. The launcher writes its Reloaded II AppConfig and AppData pointer on each start, exactly as on Windows, so a converted release keeps the package's AppConfig as an ordinary receipt-owned file and the manager does not take ownership of those files. Explicit Proton packages that declare `reloadedRoot` keep the earlier manager-owned prefix setup. The audited Time Stranger installer binary, SHA-256 `64c7721bba7a2a1070b3fceb80e8b7b28c45fba223213a720a705d80af8f0c2e`, only writes the IFEO launch registry value. Its post-install invocation is removed from the converted manifest because the Steam launch option supplies that same role. No Windows setup executable is run. The exact legacy Prism DLL, SHA-256 `3b02d1d9b2d44066604be1a6acf751c8c3c7f109c19035646aab21542083b02f`, is the official Prism 0.7.1 `prism-windows-x64.zip` `release/bin/prism.dll`. Its 42 exports keep identical signatures in 0.18.3 except for `PrismConfig`: `prism_config_init` returns version 1 (16 bytes on x64) by value in 0.7.1 and version 4 (56 bytes) in 0.18.3. A 0.7.1 consumer given 0.18.3 directly has 40 bytes past its return buffer overwritten. An earlier note here called the direct swap safe because the exports matched; that was wrong, and the Proton pilot had only worked because its unpublished mod build passed a null config. The adapter now keeps the 0.7.1 ABI at `prism.dll` through `Assets/Prism071Compat/prism_compat.c` (SHA-256 `43581ed862e787cf1ff4b3f67e3076022e63090f8116138ab136e21effefa475`, rebuilt byte-identically by `installer/linux/check-prism-071-compat.sh` with official llvm-mingw 20261006 ucrt). It returns the 16-byte config, starts Prism with defaults (version 1 has no field Prism reads), and forwards the other 40 exports to Prism 0.18.3 staged as `prism-core.dll` beside it with the bridge placeholders. This applies to any package carrying that official 0.7.1 build. An offline probe in an isolated Wine prefix (no D-Bus or display) reproduced the 40-byte overwrite with 0.18.3 alone and showed none through the adapter, which then listed Orca among Prism's backends. The adapter refuses other lifecycle binaries, unsupported speech builds, ambiguous launchers and direct NVDA-only speech. Lifecycle installers are not run under Proton: they can show Windows dialogs that a Linux screen reader cannot read. A new installer with different behavior needs its own verified Proton equivalent; the script's prose alone does not authorize skipping it. The Linux Mods list shows public and entitled Patreon releases from the signed registry, verified author indexes, and user-added sources. It also supports native Linux releases when the catalog declares a Linux executable.

## Ownership and updates

The manager verifies the package SHA-256 and manifest before installing files. It saves the old Steam option and Reloaded II configuration in a tamper-checked setup record before changing them. Uninstall restores only those owned values and uses the normal file receipt to restore overwritten game files. Uninstall always finishes: if the Steam launch option was edited after install, only the manager's wrapper text is removed and the user's own options stay; if the wrapper text is already gone, the option is left as it is. A manager-owned launcher config that changed after install is copied to `proton-setups-recovery`, beside the setup records, before the pre-install file is restored. An update re-plans the manager's launch text from the user's current options, so a release that starts differently, or a launch option the user removed, is handled without reinstalling. This port does not add a new policy for multiple mods on one game.

The wrapper keeps Steam's Proton command and game arguments intact, checks that the exact expected game executable occurs once, applies declared environment settings, and then executes Proton. It supports both the existing Time Stranger argument format and the new declarative format. In `replaceExecutable` mode it passes the game as a `Z:` path after confirming that the prefix's `Z:` drive maps to `/`; a Windows launcher that writes the path into a Windows .NET loader configuration cannot read a Unix path.
